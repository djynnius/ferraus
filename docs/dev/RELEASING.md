# Releasing

Release artifacts are produced **only** by GitHub Actions in `djynnius/ferraus`. Never upload,
sign, or publish anything built on a laptop or an agent's machine.

1. Make sure `main` is green (CI: fmt, clippy, tests on Linux x86_64/arm64, macOS, Windows;
   docs depth bar; contract snapshots).
2. Bump `version` in the root `Cargo.toml` (`[workspace.package]`) and update `CHANGELOG.md`.
3. Tag: `git tag v0.2.0 && git push origin v0.2.0`. Tag protection rules restrict who can
   push `v*` tags.
4. `.github/workflows/release.yml` (generated by cargo-dist 0.32; regenerate with
   `dist generate` after editing `dist-workspace.toml`, never by hand) builds every target,
   creates installers (`ferraus-installer.sh`, `ferraus-installer.ps1`, MSI, Homebrew formula),
   attests every artifact, and creates the GitHub Release.
5. `build-linux-packages.yml` builds and smoke-tests `.deb` and `.rpm` packages and attests them.
6. `publish-packages.yml` runs behind the `release` environment. Its required reviewers are the
   human approval gate. It verifies every artifact's attestation (`gh attestation verify`),
   then updates the apt/dnf repositories on GitHub Pages, pushes container images to ghcr.io,
   opens winget/scoop PRs, and publishes crates to crates.io.

## Secrets (in the `release` environment only)

| Secret | Used for |
| --- | --- |
| `HOMEBREW_TAP_TOKEN` | pushing the formula to `djynnius/homebrew-tap` |
| `PACKAGE_SIGNING_KEY` | signing apt/dnf repository metadata |
| `WINGET_TOKEN`, `SCOOP_BUCKET_TOKEN` | package-manager PRs |
| `CARGO_REGISTRY_TOKEN` | crates.io |
| `MODEL_REGISTRY_SIGNING_KEY` | Ed25519 signature of the model registry |
| `SOUNDS_REGISTRY_SIGNING_KEY` | Ed25519 signature of the sounds registry |
| `CODESIGN_CERTIFICATE`, `CODESIGN_CERTIFICATE_PASSWORD`, `CODESIGN_IDENTITY` | macOS signing (dist `macos-sign = true`) |
| Windows Authenticode certificate | MSI and exe signing |

## Local dry runs

`cargo build --release` and `dist build --artifacts=local` are fine for testing. Their
outputs are not attested, so the publish job refuses them even if someone tries to upload them.

See [RELEASE-SETUP.md](RELEASE-SETUP.md) for the one-time setup with exact commands.
